# 0→1 开发指南：流程、所需文档与结构

适用：新游戏，包含不同玩法｜版本：WF-1.0.0｜更新：2026-09-25｜状态：生效

## 1. 输入与职责
用户提供主要参考游戏、目标平台、主题、首版目标、时间/成本/功能限制。缺项先研究并写出假设；只有影响玩法/范围的决策才集中确认。开发任务负责拆解、实现、验证和留档，用户负责产品方向及体验验收。流程任务维护规范。

已选成熟玩法时先还原其确定的规则，不随意拼接竞品机制。规则确认不等于数值验证。内部试玩目标可以暂不发布，但明确停在何阶段。

## 2. 固定阶段与门禁
| 阶段 | 输入 | 工作与必交产物 | 完成条件 |
|---|---|---|---|
| S0 立项与参考 | 用户五项输入 | 产品需求：参考来源、日期、规则差异、首版范围、非目标；状态文件 | 主要参考和规则分歧已明确；关键产品决定获授权 |
| S1 规则定稿 | S0 | 玩法规格：合法操作、状态转移、结算顺序、失败/恢复、数值参数；关联验收标准 | 核心规则无相互矛盾；待定项明确；有具体可验证例子 |
| S2 黑白可玩版 | S1 | 平台工程、运行步骤、占位画面、完整一局、基础测试 | 能在目标平台调试并完成开始→操作→胜负→重试；浏览器先行须标记为部分完成 |
| S3 数值与关卡 | S2 | 独立配置、生成器/人工关卡、可解性验证、试玩记录 | 达到本项目明确的检查标准；算法可解与体验难度分别验收，不套用通用通关率 |
| S4 美术接入 | 主题与已确认参考 | 资源规范、素材来源授权、替换记录、界面截图 | 辨识度、遮挡层次、触控区域及适配通过；没有借美术增改玩法 |
| S5 真机与发布准备 | 可玩候选版本 | 设备测试、存档/异常/性能/广告测试、发布说明与回退方案 | 约定设备检查完成；阻断缺陷解决；账号和平台要求实际核查；未测项不得宣称完成 |
| S6 发布与观察 | S5及用户发布授权 | 版本记录、实际提交/发布结果、观察结论、问题池 | 发布状态以实际平台结果为准；无数据时标记待观察，转入迭代流程 |

阶段允许并行进行不依赖未确认内容的工作；跨阶段推进要记录影响。发布为可选终点，用户明确仅要原型时不擅自扩大。

## 3. 每个项目必须输出的文档
统一头部：适用项目、文档版本、更新日期、状态、采用流程版本、关联需求/版本。每个条目单独区分已确认、待验证、实现现状、实际结果。

| 文件 | 必备结构 | 何时建立/更新 |
|---|---|---|
| 项目入口.md | 当前可用物、运行入口、导航、限制 | 立项建立；每次交付 |
| 当前项目/00-项目状态.md | 阶段、版本、完成项、在做、阻塞、待确认、下一步 | 每轮开工核对，结束更新 |
| 当前项目/01-产品需求与范围.md | 目标、受众、参考证据、范围/非范围、用户流程、REQ及验收 | S0；范围变化时 |
| 当前项目/02-玩法规则与关卡数值.md | RULE、状态/顺序、边界、参数入口、生成/求解、难度假设 | S1；规则/数值变化时 |
| 当前项目/03-技术架构与资源规范.md | 平台/目录、通用与玩法边界、配置/存档、广告、资源、依赖授权、运行发布 | S2；架构/资源变化时 |
| 当前项目/04-版本与决策记录.md | 版本、决定、依据、授权、影响、验证、回退 | 每轮 |
| 测试与验收/00-测试与验收记录.md | TEST→REQ/RULE、步骤、预期、实际、环境版本、证据、缺陷、体验验收 | S1开始写预期；执行后填结果 |

参考证据可写入需求文档，无需另建长报告。较大附件按版本放 artifacts/，文档链接引用；不把自动化输出全文堆进交付消息。

## 4. 建议目录
```text
项目根目录/
├─ 项目入口.md
├─ AGENTS.md
├─ 文档/
│  ├─ 00-目录导航.md
│  ├─ 01-开发与迭代指南/（两份指南、流程版本说明、模板）
│  ├─ 02-当前项目/（状态、需求、规则数值、架构资源、版本决策）
│  ├─ 03-迭代记录/（问题池与各轮迭代单）
│  ├─ 04-测试与验收/
│  └─ 05-参考资料/
├─ minigame/        实际创建后才是微信导入目录
├─ prototypes/      辅助原型，非正式平台验收
├─ assets/          原始美术与音频
├─ tests/
├─ tools/
├─ artifacts/版本号/ 测试证据与交付物
└─ .cache/          可重新生成的临时产物
```
按实际需要建目录，不用空文件伪装进度；平台要求的文件留在正确工程位置。项目配置文件允许位于根目录。

## 5. 跨玩法复用方法
复用流程和文档模板；通用底座须实际验证后才作为模板版本发布。叠牌的遮挡、三消、求解器不能当倒水规则直接复用。倒水项目重写规则模块与关卡验证，复用适配、存档框架、按钮弹窗、广告网关和测试运行工具。各项目绑定底座版本；升级通过独立迭代验证。

新项目只复制空白模板、已验证底座与许可证信息，清空完成记录、广告 ID、AppID、旧数值结论和历史任务状态。

## 6. 每轮交付检查
- 本轮授权范围内功能和文档完整；不得混入额外机制。
- 必要测试已运行，设备/版本/结果可查；待验证独立列出。
- 目录归属、相对链接、启动入口、测试路径正确；原有用户资料保留。
- 更新状态和版本记录，交付明确下一步；跨任务交接注明 WF 版本。
- 批量复用验收：同玩法第二款尽量只换配置和资源；跨玩法第二款明确记录真实复用部分与新增部分，不提前宣称万能模板完成。
