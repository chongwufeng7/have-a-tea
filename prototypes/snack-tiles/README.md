# 中式小吃叠牌消除 · 低保真原型

直接打开本目录的 `index.html` 即可试玩；也可在项目根目录运行 `npm start`，访问 http://127.0.0.1:4173 。不需要安装依赖。在项目根目录运行 `npm test` 验证核心逻辑。本说明属于历史原型技术说明，项目现状以根目录《项目入口.md》及当前项目文档为准。

## 已实现

- 黑白响应式页面，以小吃名称与编号代替美术。
- 30 关、选关、重开、三消、遮挡、七格暂存、胜负结算、三种道具。
- 每关每种道具免费 1 次，重开恢复。没有体力、计时或额外养成。
- 本机保存完成关卡与最近选关，不保存进行中的对局。全部关卡在原型中开放。

牌数、种类、层数仅为难度代理值，不保证每关实际难度单调上升。初始关卡均由固定种子生成，沿合法移除顺序安排成组三张，附有可自动验证的通关见证；这是可解性保证，不代表每一步任意选择都可通关，也不代表已经完成商业数值调优。后续需以真实试玩的通关率、重试次数、道具使用率校准。

## 确定的规则

1. 上层矩形牌与下层牌重叠即遮挡；只允许点完全未遮挡的牌。
2. 牌按点击顺序进入槽内；同类满三张立即消除。先消除再检查七格满槽。
3. 棋盘、槽内、临时区所有牌都消除才获胜。
4. 撤回完整还原最近一次选牌，包含该次消除。撤回次数不会随还原恢复。洗牌或移出后清除撤回记录。
5. 洗牌仅打乱棋盘剩余牌的类型，不改变数量、坐标、遮挡、槽内及临时区；不保证当前局面洗牌后必有解。
6. 移出将最早入槽的三张放入独立临时区，只能在临时区为空且槽内至少三张时使用。移出不是销毁，需要点回槽内继续消除。
7. 失败时可以用剩余的撤回或移出恢复，否则重开。重开是相同牌局。

## 广告接入预留

`ads.js` 定义 `AdGateway`，默认 `enabled:false`，无 SDK、无请求、无可见广告按钮。

| placement | 后续用途 | 当前状态 |
|---|---|---|
| reward.undo | 看完激励视频，补充一次撤回 | 接口预留，未开放 |
| reward.shuffle | 看完激励视频，补充一次洗牌 | 接口预留，未开放 |
| reward.remove | 看完激励视频，补充一次移出 | 接口预留，未开放 |
| interstitial.settlement | 完成关卡后的可选插屏 | 继续下一关时调用关闭的网关 |

未来的小游戏适配层实现 `provider.rewarded(placement)` 和 `provider.interstitial(placement)`。只有平台 SDK 明确确认视频完整观看，才能返回 `{completed:true}`，再用 grant 回调补充道具。取消、加载失败不能发奖；请求期间互斥。当前免费道具按钮不依赖广告。

正式接入时仍需实现平台 SDK 生命周期、广告频控、过期局面保护（观看中换关不应给新关发奖）及真机验证，不能只打开开关。没有预留常驻横幅以免占用棋盘，也没有接入真实广告 ID。

## 范围与限制

这是浏览器里的玩法原型，不是已经打包上架的微信小游戏。还需要小程序游戏环境适配、原创美术替换、真机性能和发布流程。当前不包含音效、账号、排行、支付或后台。生成器不依赖外部开源游戏代码。
